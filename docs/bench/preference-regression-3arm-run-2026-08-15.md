# PreferenceRegression 3팔 실측 — 유효성 회차 (#459, #343 후속 조각 1/2) — 2026-08-15

## 판정

**이 회차가 세우는 것은 수치가 아니라 「비교가 성립한다」는 사실이다.** #401 실측이 드러낸
두 측정 장치 결함 — (1) retrieval 무주입 ON 에피소드가 OFF보다 적게 받던 비대칭, (2)
`concise-responses`의 천장이 ORACLE에서도 막혀 있던 결함 — 을 고친 뒤 같은 3팔·3시나리오를
`deepseek-v4-flash`로 재실행했다. **이 회차의 ON 수치는 배선 전 기준선이다** — ON 팔에
`ConversationSource`를 붙이는 배선(#343 후속 조각 2/2)은 아직 하지 않았고, 그 작업이 끝난
뒤에야 이번 수치와 비교해 "배선의 효과"를 읽을 수 있다.

킬 스위치(#435)는 3개 시나리오 모두 통과했다 — `concise-responses`도 이번엔 ORACLE−OFF
간격이 0.5로 임계값(0.25)을 넘어 무효 판정을 받지 않았다. 완료 조건이 요구한 것은 이
판별 가능성이지 특정 방향의 델타가 아니다.

**단서 — 이번 회차의 압축 요약은 내용이 비어 있다.** 이 회차의 압축 요약 6건
(`tabs-indentation`·`concise-responses` × OFF·ON)은 전부 "The conversation is empty —
there is no user request or task to summarize" 류의 공통 보일러플레이트였다(원본 JSON
`compactionSummary` 필드 참고). 그런데 이 시나리오들의 맥락 세션(`scenarios.ts`
`contextTurns`)은 실제로 3~4턴의 구체적 대화를 담고 있다 — 압축 대상이 비어 있을 이유가
없다. 즉 **§2의 "ON ⊇ OFF가 배선상 보장된다"는 명제는 배선 수준에서만 성립**하고, 내용
수준에서는 공허하다 — ON 팔이 폴백으로 받은 것과 OFF 팔이 원래 받던 것이 "같다"는 것이지,
그것이 유의미한 사용자 습관 요약이라는 뜻은 아니다. 원인은 pi 기본 `compact()` 경로가 맥락
세션의 대화 내용을 제대로 못 읽는 것으로 보이며(이 PR의 결함이 아니다 — #401의 2026-08-14
리포트에도 같은 패턴이 이미 있었다), 원인 추적은 **#462**(진단 전용, 이 PR과 파일 교집합
없음)로 분리했다. 이 단서는 위 「배선 전 기준선이다」 선언과 나란히 읽어야 한다 — 다음
회차가 이번 +0.333 델타를 "유의미한 이월 내용의 효과"로 과대해석하지 않도록.

## 1. 팔별 점수

`--repeats 1`, 시나리오 3건 × 팔 3개 = 9 에피소드.

| 시나리오            | OFF   | ON    | ORACLE | ORACLE−OFF | 킬 스위치   |
| ------------------- | ----- | ----- | ------ | ---------- | ----------- |
| `tabs-indentation`  | 0.0   | 0.0   | 1.0    | 1.00       | 통과        |
| `concise-responses` | 0.0   | 0.0   | 0.5    | 0.50       | 통과        |
| `pnpm-workflow`     | 0.0   | 1.0   | 1.0    | 1.00       | 통과        |
| **평균**            | 0.000 | 0.333 | 0.833  | 0.833      | 임계값 0.25 |

**행동 적응 델타 (ON−OFF) = +0.333.** #401의 −0.167과 부호가 다르지만, 서로 다른 세션의
LLM 출력을 비교하는 것이므로 이 반전을 "폴백이 이득을 냈다"는 인과로 읽지 않는다 — 표본이
시나리오당 1개뿐이라 어느 방향이든 노이즈 안에 있다. 이 회차가 확정하는 것은 델타의 부호가
아니라, ON이 더 이상 "압축 요약조차 없는 맨 세션"으로 떨어지지 않는다는 배선상의 보장(§2)과
`concise-responses`가 이제 기억 유무를 판별할 수 있다는 것(킬 스위치 통과)이다.

## 2. 계기판 — 주입 적중률 + 폴백 발동

| 지표                             | 값        | 비고                                                                                                     |
| -------------------------------- | --------- | -------------------------------------------------------------------------------------------------------- |
| `injectionHitRate` (주입 적중률) | **0.333** | ON 팔 3건 중 `pnpm-workflow` 1건에서만 mori retrieval이 주입됨                                           |
| 폴백 발동 (`fallbackUsed=true`)  | **2건**   | `tabs-indentation`, `concise-responses` — retrieval 무주입이라 OFF와 동일한 하네스 압축 요약을 대신 얹음 |
| 폴백 미발동 (retrieval 적중)     | 1건       | `pnpm-workflow` — organic 주입이 있어 폴백이 개입하지 않음                                               |
| `reQuestionRate` (재질문율)      | 0.000     | —                                                                                                        |
| `reDistillationRate` (재증류율)  | 0.000     | —                                                                                                        |

`injectionHitRate`는 여전히 0.333으로 #401과 같다 — 폴백 발동 2건이 적중률 계산에 섞이지
않는다는 뜻이고, 이것이 완료 조건 3("폴백을 적중으로 세지 않는다")의 실측 증거다.
`tabs-indentation`·`concise-responses` 에피소드는 폴백 덕에 OFF와 같은 머리말을 받았고,
그 결과 두 에피소드 모두 ON=OFF(둘 다 0점)로 나왔다 — #401에서처럼 ON이 OFF보다 **낮게**
나오는 비대칭은 이번 회차에 없다.
